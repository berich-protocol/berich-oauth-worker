> **プロジェクトの概要：**
> PC 上で使われていない余剰の AI 有料サブスクリプション（Claude Pro/Max、ChatGPT Plus/Pro、Google Gemini）をローカルの認証済み公式 CLI を通じてコミュニティと共有し（API キーの提供は不要）、**ノードのオンライン中に [BeRich (`https://berich.cc`)](https://berich.cc) の台湾株ザラ場 VIP 特権とモデル間相互クォータを獲得**しながら、計算リソースを**標準 OpenAI 互換 API ゲートウェイ (`/v1/chat/completions`)** に集約します。

---

## 🔄 主要機能と2つの用途

**[`https://berich.cc/compute`](https://berich.cc/compute)** にアクセスすると、2 つの主要タブを確認・利用できます：

### 1. タブ：「サブスク共有で VIP 獲得」（`分享訂閱換 VIP`）
- **余剰サブスクの共有**：端末の放置時にローカル公式 CLI を介して推論タスクを中継します。
- **台湾株ザラ場 VIP 特権**：Worker ノードをオンラインに維持することで、ログイン済みの BeRich 正式会員アカウントはオンライン中に台湾株ザラ場 VIP 特権（ザラ場中の実銘柄コード即時表示および実売買ポジション追跡）が自動的に適用されます。
- **モデル間相互クォータ**：オンライン貢献者は 1 日あたり基準として 100,000 Tokens の API ゲートウェイ相互呼び出し枠を獲得します（検証済み保有枠が大きい場合は大きい方を適用）。
- **⚠️ 特権の帰属について**：台湾株ザラ場 VIP は正式ログイン会員専用の特権です。VIP 特権を紐付けるため、必ず事前に BeRich にログインした状態で起動コマンドを取得してください。匿名セッションで起動した場合、API 呼び出し枠は付与されますが、サイトの台湾株 VIP 会員特権は付与されません。

### 2. タブ：「無料 AI 利用（例：OpenClaw ロブスター）」（`免費用 AI（例如龍蝦 OpenClaw）`）
- **標準 OpenAI 互換 API ゲートウェイ**：ネットワーク全体のノードを集約した標準 API ゲートウェイ（`https://berich.cc/api/v1`）。
- **外部クライアント接続例**：カスタム OpenAI エンドポイントに対応したクライアント（例：**OpenClaw（龍蝦）**）に Base URL と API キーを設定し、テキスト対話生成を実行できます。
- **⚠️ クライアント利用の制限事項**：OpenClaw は互換クライアントの接続例としてのみ提示しています。本ゲートウェイは純粋なテキスト形式のみをサポートしており、`tools` や `tool_choice` パラメータは拒絶され、`tool_calls` や Function Calling ワークフロー、マルチモーダル入力には非対応です。完全な自律エージェントやツール自動実行への対応を意味するものではありません。

## 🛠️ 前提条件と起動方法

### 前提条件
1. **Python 環境**：Python のインストールが必要です（CI テスト環境は Python 3.11；Worker スクリプトは 100% Python 標準ライブラリのみを使用し、`pip install` による追加ライブラリのインストールは一切不要です）。
2. **公式 AI CLI ツール**：端末に以下の公式 CLI が事前にインストールされ、公式ログインが完了している必要があります：
   - **Claude Pro / Max**: `claude auth login`
   - **ChatGPT Plus / Pro**: `codex login`
   - **Google Gemini**: `gemini`（起動後に Sign in with Google を選択）
   - インストールやログイン方法が不明な場合は、各 CLI の最新公式ドキュメントをご参照ください。

### 起動手順
1. **[`https://berich.cc/compute`](https://berich.cc/compute)** の「**分享訂閱換 VIP**」タブを開きます。台湾株 VIP を利用する場合は、あらかじめ会員ログインを完了させてください。
2. 契約中のサブスクと OS を選択します。
3. 画面上の **「取得本機啟動指令」**（ローカル起動コマンドを取得）ボタンをクリックし、生成された完全なコマンドをコピーします。
4. コピーしたコマンドをそのまま端末に貼り付けて実行します。**パラメータの手動変更やノード ID の書き換えは行わないでください**（ウェブコマンドは認証トークン付きの Node ID、プロバイダリスト、任意のアイドル避譲オプションを自動で束ねています）。
5. **トークンと API キーの分離**：`bw_oauth_...` は Worker 通信用の認証トークンであり、API 呼び出し用の API キー（`sk-berich-...`）とは厳格に分離されています。起動コマンドや秘密鍵を外部に公開・共有しないでください。
6. **Worker の更新**：Worker コードがアップデートされた際は、既存のプロセスを停止し、最新の起動コマンドを再取得して再起動してください。

## 🔑 API キーの自動発行とモデルカタログ

### 1. 自動発行とキー管理
- 署名済みまたはログイン済みの所有者が正規の Worker を起動・登録すると、サーバーは専用の API ゲートウェイキー（`sk-berich-...`）を自動作成または既存キーを再利用します。
- ノードの再接続や再起動を行っても、同一のキーと当日の累積利用量が保持され、再接続ごとに自動ローテーションされることはありません。
- ターミナルおよび登録レスポンスにはマスクされたキー（例：`sk-berich-...***`）、API Base URL、および現在オンラインのモデルのみが表示されます。完全なキーは、ログイン済み会員または**同一のサーバー署名 Cookie を保持する匿名ブラウザセッション**から `https://berich.cc/compute` で確認・コピーできます（匿名識別はサーバー署名 Cookie により管理され、ウォレット署名は必須ではありません）。

### 2. API 仕様とエンドポイント
- **API Base URL**: `https://berich.cc/api/v1`
- **チャット補完エンドポイント**: `POST https://berich.cc/api/v1/chat/completions`
- **モデルカタログエンドポイント**: `GET https://berich.cc/api/v1/models`
  - 各モデルのリアルタイム在籍キー数 `active_pool_keys` が返却されます。
  - クライアント側では `active_pool_keys > 0` のモデルをフィルタリングして実利用可能な候補として選択してください。

### 3. 動的供給と制約事項
- **固定数および常時オンラインの非保証**：プール内のモデルはコミュニティノードのオンライン状況に依存します。固定モデル数の保証や、有料フォールバックキーによる自動補填はありません。あるモデルのオンラインノードが 0 の場合、リクエストは拒絶されます。カタログに掲載されていること自体が即時利用可能性を保証するものではありません。
- **純粋なテキスト形式とツールの制約**：メッセージの `content` はプレーンテキスト文字列である必要があります。ゲートウェイは `tools` および `tool_choice` を明示的に拒絶し、`tool_calls` や Function Calling ワークフロー、画像・音声などのマルチモーダル入力を受け付けません。
- **SSE ストリーミングの特性**：現在の SSE ストリーミングは、バックエンドが上流から回答全体を受信した後にチャンク分割してクライアントへ送信する仕組みを採用しており、上流からのリアルタイム逐次トークンストリーミングではありません。

## 📊 クォータ規則と VIP 特権

### 1. 日次 API クォータの計算式
- **基本試用クォータ**：一般ビジターは 1 日 3,000 Tokens。
- **オンライン貢献者枠**：ノードが実際にオンラインを維持している間、基準として 100,000 Tokens/日 が付与され、検証済み保有枠が大きい場合はそちらを適用：`max(100,000, 認証後保有枠)` Tokens/日。
- **Web3 ウォレット署名と保有枠**：
  - Web3 ウォレットによる署名検証と残高確認が必要です。**トークンをウォレットに保有しているだけでは、VIP 特権やザラ場機能は付与されません。**
  - 保有枠の計算式：`int(balance * 0.5)`。
  - 通常時の日次上限：`max(3,000, 保有枠)`。
  - 50,000 $BRICH 以上保有の場合：日次下限が 25,000 Tokens となり `max(25,000, 保有枠)`；有効な非貢献者 VIP 会員にも 25,000 の下限が適用される場合があります。
  - **重要ルール：オンライン共有枠と保有枠は「大きい方を選択 (`max`)」し、合算（加算）はされません！**
  - 基準試算例（計算式は固定階層ではなく任意の残高に対応します）：
    - 0 $BRICH: 3,000 Tokens/日
    - 50,000 $BRICH: 25,000 Tokens/日
    - 200,000 $BRICH: 100,000 Tokens/日
    - 2,000,000 $BRICH: 1,000,000 Tokens/日
- **クォータ更新時刻**：台湾時間 毎日 08:00（UTC 00:00）。
- **オフライン時の処理**：ノードがオフラインになるか認証が失効した場合、オンライン共有資格は直ちに終了し、検証済み保有枠または基本枠にフォールバックします。オフライン中に VIP 日数が累積されることはありません。

### 2. 台湾株ザラ場 VIP 比較表
ノードがオンライン中、ログイン済み会員に適用される機能比較：

| 項目 | 一般ビジター | VIP 会員 |
| :--- | :--- | :--- |
| ザラ場 AI 銘柄選定 | ザラ場中は銘柄コード非公開、15:00 大引け後に公開 | ザラ場中にリアルタイムで銘柄コードを表示 |
| 実売買ポジション追跡 | ザラ場中は銘柄コード非公開、15:00 大引け後に公開 | ザラ場中にエントリー・利確・損切りラインを同期表示 |

### 3. ノード報酬とクレジット
- ノード登録や読み取り専用の検証で即座に報酬が発生することはありません。
- ログに表示される貢献クレジットは、実際に引き受けて正常に完了した推論タスクの決済に基づいて累積されます。オンチェーン出金やミント、収益を保証するものではありません。
- コントラクトアドレス（Base チェーン）：`0x86D4854150c11b606081f8101Bf239A0c110999E`（技術的識別用であり、投資・財務上の助言ではありません）。

## 🛡️ 会話内容の完全暗号化 (`br_enc_v1` AEAD)・動作メカニズム・リスク開示

1. **全会話内容のエンドツーエンド＆メモリ暗号化 (`br_enc_v1` AEAD)**：
   - **認証付き暗号化通信**：タスク配信（`/api/compute/tasks/claim` の `prompt`）および推論結果提出（`/api/compute/tasks/submit` の `result`）はすべて 100% Python 標準ライブラリによる `br_enc_v1` AEAD 方式（`HKDF-SHA256` 鍵導出 + 128-bit ランダム Nonce + `SHA256-CTR` 暗号 + `HMAC-SHA256` Encrypt-then-MAC、関連データ `berich-e2ee-v1|{direction}|{task_id}|{node_id}` AAD バインド）で暗号化され、改ざんやリプレイ攻撃を防止します。
   - **サーバー RAM 暗号化と即時消去 (Zeroization)**：処理中のタスクもサーバー RAM 上で暗号化保持され、クライアントへ応答を返した瞬間にメモリキューから完全消去されます（DB 保存なし、会話ログ記録なし）。
   - **ローカル履歴ゼロ＆インジェクション防御**：モデル名の厳格なホワイトリスト検証（`--` フラグ注入の遮断）、`HISTFILE=/dev/null` 等の履歴無効化環境変数の適用、およびログへの平文・トークン出力禁止を徹底しています。
2. **ローカル CLI 実行と認証情報の取扱い**：Worker は端末上の公式 CLI を介して推論を中継します。公式 CLI は実行時にローカルのログイン設定や認証情報を読み込み、リクエストはルーティングおよび公式上流サーバーを経由します。一時ディレクトリの指定や `--tools ""` によりリスク低減を図っていますが、**完全なシステムサンドボックス隔離ではなく、ローカルファイルへのアクセスが一切発生しないことを保証するものではありません**。
3. **事前アイドル判定 (Idle Guard)**：アイドル避譲はオプション機能です（ウェブ画面の生成コマンドにはデフォルトで `--idle-only` が付与され、デフォルト閾値は 60 秒 `--idle-threshold 60.0` です）。有効時、Worker はタスク取得前および CLI 呼び出し前にシステムアイドル状態を確認し、判定失敗またはユーザー操作検知時はタスク取得を停止します。**CLI が既に実行中の場合、マウスやキーボードの操作があっても実行中のプロセスが即座に強制終了されることはありません**。現在の処理が完了した後、操作が検知された場合に次タスクの取得が一時停止されます。`--idle-only` を付与しない場合、Worker は常時タスクを受注します。
4. **OS ごとのアイドル判定の差異**：macOS（`ioreg`）および Windows（`GetLastInputInfo`）はネイティブのアイドル取得に対応しています。Linux 環境では現在アイドル取得が `None` を返すため、安全保護（Fail-Closed）により `--idle-only` を有効にするとタスクを取得できません。**Linux は完全なアイドル避譲モードをサポートしていません**。
5. **サービス側での利用量推計**：サービス側バックエンドが 5 時間ローリング利用量を推計し、コミュニティプールの容量管理および 75% ソフトリミット保護を実施します。ローカル Worker が公式クォータを直接追跡するものではありません。この推計値は公式上流の実際の残余クォータを照会するものではなく、25% の公式枠確保を保証するものでもありません。
6. **フィルタリングとマスキングの限界**：組み込みのキーワード検証や正規表現マスキングは補助的なリスク低減手段であり、完全な安全性や完全な匿名化を保証するものではありません。
7. **利用規約とアカウント停止リスクの非保証 (No Ban Guarantee)**：本プロジェクトはオープンソースの分散技術検証であり、アカウント停止（BAN）のリスクがゼロであることを保証するものではありません。各 AI 提供元の規約改定等を考慮し、ユーザー自身の責任においてご利用ください。

## 🧪 オフラインシミュレーション検証 (Offline Simulation Check)

ターミナルでシミュレーションスクリプトを実行し、設定やローカル転送ロジックを検査できます：

```bash
python3 prove_it_works.py
```

> **ご注意**：本スクリプトはオフラインのモック検査（外部通信および公式上流 API との接続なし）であり、テスト用フィクスチャやパラメータ構築をローカル検証するものです。**実際の CLI や公式上流との完全な互換性、安全性の公的認証を証明するものではありません。**
- **AST 静的構文解析**：`berich_worker.py` の標準ライブラリ構成と構文構造の検査。
- **事前判定とパラメータ生成**：OS アイドル時間取得、CLI パラメータ組立て、およびフラグ注入防止の検証。
- **複数サブスク登録モック**：ローカルモックサーバーでの複数プロバイダ登録とトークン非露出の確認。
- **暗号化タスク割り当て＆即時消去モック**：`br_enc_v1` AEAD 暗号化・復号、HMAC 改ざん検知、および完了後のメモリ即時消去のシミュレーション。
- **クォータ枯渇フェイルオーバー**：429 エラー分類とキュー再挿入のテスト。
- **フィルタとマスキング検証**：キーワード判定と正規表現による伏字化テスト。
